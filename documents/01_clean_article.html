How DNS Works (Simplified)

When you type a website name such as www.example.com into a browser, your computer still needs a numeric IP address to make the connection. The Domain Name System (DNS) is the Internet's lookup service for that translation.

Your computer first checks a small local cache of recent lookups. If the name is not cached, it asks a resolver, usually provided by your network or a public resolver. The resolver may already know the answer, or it may walk the DNS hierarchy to find it.

The hierarchy starts at the root nameservers, which point to the nameservers for a top-level domain such as .com. Those servers then point to the nameservers that hold the records for example.com, which finally return the IP address for www.example.com.

Once the address is found, it is cached for a short time (the TTL) so the next visit is faster. If a DNS record is wrong or a lookup is intercepted, a user can be sent to the wrong host, which is why DNS security extensions (DNSSEC) and encrypted DNS matter in practice.

In short: DNS is a distributed directory. Browsers, mail servers, and almost every other Internet service depend on it every day.
